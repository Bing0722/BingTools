# BingTools 0.6.0

本次发布汇总自 0.4.5 以来的 TCP 服务器仿真功能。

## 新增 / Added

- 服务器仿真新增 TCP 服务端客户。按 HEX 结束符分帧后，可从 JSON 对象字段路径或按分隔符切开的文本字段提取值，并与接口名称精确匹配，返回固定 JSON／文本。接口开关与保存可在运行中生效；无效或未匹配消息只记日志，不回复。
- TCP 客户可选「长度头 + 正文 + 结尾标志」分包：支持 1–10 位固定宽度 ASCII 十进制／十六进制长度头，按 UTF-8 字节或 Unicode 码点计数，长度可表示正文或整包。按声明长度定位并校验 HEX 尾标，再提取 JSON／文本字段。正文中可以包含与尾标相同的字节。
- 长度头模式可自动为回复生成同规则包装。头、UTF-8 字符和尾标拆包或多帧粘连均可处理；非法头、超限声明或错误尾标会断开对应连接，不猜测边界。原有结束符分包模式保持可用。
- 每连接独立缓存，最多 64 个连接；单帧与回复上限各 1 MiB，空闲连接 60 秒关闭，停止服务释放端口。旧 HTTP／TCP 配置迁移到 `simulator.json` schema v3，原有行为保持。

例如 `0016{"action":"get"}#` 使用 4 位十进制正文长度、尾标 `23`；字段 `action` 的值匹配名称为 `get` 的接口。

## 安装与限制 / Installation and limitations

- Windows x64 安装包未签名，可能显示未知发布者；Windows 实机安装升级、用户设备协议及长时间高并发尚未验收。
- macOS Apple Silicon 安装包未签名、未公证，需从 GitHub 手动下载安装；应用内不执行原位自动安装。
- 本机设置与客户配置保存在用户数据目录，HTTP／TCP 服务均需手动启动。TCP 仅作为服务端，不支持 TLS、二进制整数长度头、校验和、脚本或自动识别协议。

Since 0.4.5, this release adds a TCP server simulator with JSON/text field routing and optional ASCII length-header framing. It supports bounded connections, split and coalesced frames, and framed replies. Windows installation and real device protocols remain unverified; unsigned macOS builds require manual updates.
