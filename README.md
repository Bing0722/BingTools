# BingTools

基于 Electron 的本地 HTTP／TCP Mock 与运控串口仿真工具。左侧导航，右侧配置客户、通过卡片管理接口，下方实时查看请求日志。

当前版本 0.6.0：TCP 字段提取与接口名称匹配、客户管理、HTTP 监听、接口独立开关与运行中更新、JSON／文本响应、日志筛选与脱敏、应用内通知、简中／英文／跟随系统。保留主题、侧栏和本地设置；旧演示页面已移除。顶部为统一自定义标题栏，macOS 原生按钮独立留白，Windows 默认隐藏菜单栏；侧栏支持平滑展开与收起。

## 已确定的方向

- Electron + React + TypeScript，使用 electron-vite 开发与构建，electron-builder 打包。
- Tailwind CSS + shadcn/ui 构建界面，Lucide React 提供图标。
- React Router 管理页面，Zustand 管理确有共享需求的界面状态。
- 采用克制、中性、紧凑但清晰的桌面工作台风格，支持浅色、深色和跟随系统。
- Node 内置 HTTP 在主进程运行服务，受控 IPC 隔离系统能力；i18next + react-i18next 提供即时语言切换。

这些是项目选型，不代表参考产品使用了相同技术。初始化时应核对依赖兼容性，锁定版本并提交锁文件。

## 本地运行

需要 Node.js 22.13+（建议 Node 22 LTS 的最新补丁）及 pnpm 11.5.2。

```sh
pnpm install
pnpm dev
```

安装脚本会准备 Electron 运行时。开发环境提供界面热更新。关闭窗口后，macOS 上应用仍可驻留；使用应用菜单“退出”或 Cmd+Q 完全退出。

```sh
pnpm typecheck       # TypeScript 检查
pnpm lint            # ESLint 检查
pnpm test            # 真实 HTTP、持久化与边界测试
pnpm build           # 生产构建
pnpm start           # 运行已构建版本
pnpm test:motion     # 运控页面与原生串口枚举验证，不连接硬件
pnpm test:desktop    # 真实 Electron 自动验证，先执行 build
pnpm package         # 本机可运行的应用目录
pnpm package:mac     # macOS ZIP 包
pnpm package:release # 配置仓库后生成更新发布包，仅本地构建，不上传
```

macOS Apple Silicon 的本机产物位于 `release/mac-arm64/BingTools.app`。当前使用 Electron 默认图标，未签名、未公证。Windows x64 与 macOS ARM64 由 GitHub Actions 原生打包，测试与发布结果见验证记录。

打包配置复用安装好的 Electron 分发目录，只打包当前平台及架构。跨平台或跨架构打包应移除或调整 `build.electronDist`，再准备对应目标的运行时；串口原生绑定使用随包提供的 Node-API 预构建文件；主进程将 serialport 保持为外部依赖，electron-builder 自动解包原生文件。本机加载验证见验证记录。

## 数据与验证

正式设置存放在 Electron `userData` 目录下的 `settings.json`；macOS 默认位于 `~/Library/Application Support/BingTools/`。包括主题、语言、侧栏偏好和窗口位置；v1/v2 设置会迁移到 v3，补齐通知位置偏好。客户及接口独立存入 `simulator.json`。损坏文件会备份，未知的更高版本不会被覆盖。日志和通知只存在当前会话。

桌面测试使用独立临时目录，不修改正式设置。测试截图输出到已忽略的 `test-results/`。

依赖版本与 `pnpm-lock.yaml` 已锁定。使用 npm 官方源及 `pnpm install` 默认在线模式；在线连接失败时先修复，不退回离线安装。之前为了离线缓存添加的间接依赖覆盖已移除。shadcn 风格的基础组件采用 Radix + CVA 在本地维护，配置入口为 `components.json`。

每完成一轮有意义的修改，检查差异、执行相关验证并进行 Git 本地提交。只提交当前任务相关文件，不自动推送远端。

## 使用流程

1. 在服务器仿真页新增客户，设置本机监听 IP 和端口，默认 `127.0.0.1:8080`。
2. 新增接口，在弹窗中填写方法、路径和响应，打开启用开关并保存。点击卡片可再次编辑。
3. 点击启动服务，使用外部客户端访问，例如 `curl http://127.0.0.1:8080/api/example`。
4. 日志面板查看请求结果，点击记录查看脱敏请求头和截断后的正文预览。
5. 接口开关和保存立即作用于后续请求；切换客户或修改监听地址前先停止。

支持固定 JSON／文本 HTTP 和 TCP 响应；不执行脚本，不支持 HTTPS 或自动启动。请求和响应上限各 1 MiB；日志预览各 8 KiB。关闭窗口停止服务，重新打开不会自动监听。

## 应用更新

设置页连接 [GitHub Releases](https://github.com/Bing0722/BingTools/releases)，显示统一版本号及更新说明。Windows 提供检查、下载和重启安装流程；macOS 暂未签名，提供 GitHub 下载页手动更新。

推送 main 自动测试和打包；推送与 package.json 一致的版本标签（如 `v0.6.0`），两个平台成功后自动发布安装包、更新元数据和更新说明。见 [发布指南](./docs/updates.md) 与 [更新记录](./CHANGELOG.md)。

JSON 响应支持“美化 JSON”（两空格缩进）和输入时格式校验；错误内容保留原文，保存前再次校验。美化后需点击保存接口才会生效。

页面切换、日志开合、弹窗与常用控件采用统一轻量动效，支持系统减少动态效果。接口开关使用局部忙碌状态；仿真操作错误通过通知查看，不再挤占客户配置区域。

客户下拉框仅在无客户时显示“—”。新增客户可选择复制已有客户的监听配置及全部接口；“编辑客户”可改名并保留接口。名称不可重复（忽略首尾空格和英文大小写），复制和编辑前需停止服务。

接口中间区域采用卡片网格；拖动右上角手柄到目标卡片可排序，也可聚焦手柄后用方向键前后移动。顺序按客户保存，重启保留。编辑弹窗支持 JSON 美化、保存和关闭时的未保存提醒；上方客户配置及下方日志保留。

通知仅用于错误、服务启停及可用更新等重要事件；侧栏、主题、语言及普通保存操作不弹成功通知。设置 → 通知可选择四角显示位置，默认右下角，即时生效并在重启后保留。

## 运控串口仿真（0.4.0）

左侧「运控仿真」拥有独立客户配置，可新增、复制、改名、删除客户；通过「编辑客户」选择系统已存在的串口并设置波特率、数据位、停止位、校验位和 RTS/CTS。Windows 使用 COM 端口，macOS 使用系统设备路径。本应用打开已有串口，不创建虚拟串口对。

接口卡片配置「收到的内容 → 回复内容」，支持 UTF-8 文本与 HEX；按完整帧字节精确匹配，文本空格不自动忽略。同一客户不允许重复接收字节。自动应答可独立开关；连接后点击「发送」主动发送该接口回复内容，即使自动应答关闭也可发送。卡片可拖动或方向键排序，弹窗编辑有未保存保护。

默认 9600 / 8N1，按 `0A` 换行分包；可配置 HEX 结束符、定长或空闲间隔。结束符匹配时剥除，发送时可勾选追加。收发内容最多 64 KiB，超长帧丢弃；发送队列最多 100 项，写入超时或断开停止连接，不自动重连。HTTP 与串口可独立运行；每个模块各运行一个客户。关闭窗口会停止两者，重开不自动连接。

串口日志每 100ms 批量推送，只保留最近 2000 条，每条预览最多 2 KiB，虚拟列表只绘制可见行；支持收发方向、关键词筛选、详情、清空和暂停自动滚动（继续接收）。普通消息不弹通知。配置保存到独立 `userData/motion.json`，日志不写磁盘。

无硬件时可先编辑配置；连接前需选择系统枚举到的端口。已验证本机串口模块加载与 Mock 收发；真实设备和 Windows COM 实机尚待验证。

接口编辑新增接收尾部处理：分包后先移除一次指定 HEX 尾符（若存在），再忽略 0–256 个末尾字节，随后与「收到的内容」精确匹配。例如设备发送 `POS?\r\n`、客户分包结束符为 `0A`，接口接收填 `POS?`，移除尾符填 `0D`，忽略字节数为 0。若回车前还有 1 个校验字节，则忽略字节数设为 1。这里不计算或验证 CRC；按字节而非显示字符计数，ASCII 字符 `AB` 是 2 字节，HEX 字节 `AB` 是 1 字节。日志保留分包后、尾部处理前的原帧；多条规则同时匹配时不回复，日志记录歧义。默认不开启处理，旧配置自动迁移保持原有行为。

标题栏通知旁提供检查更新入口，检查结果与设置页同步；发现新版本显示红点，点击可查看说明与下载／安装操作。不自动下载或安装。

HTTP 与运控日志面板各自保留当前会话的收起、搜索、筛选、暂停滚动及滚动位置，切换页面不重置；重新启动应用恢复默认。

## TCP 服务器仿真（0.5.0）

在服务器仿真中新增／编辑客户，连接方式选择 TCP，配置监听 IP、端口和消息结束符。默认 `0A`（LF），CRLF 用 `0D0A`；每个完整消息必须携带结束符，结束符不得出现在消息正文中。JSON 建议单行发送。本应用是 TCP 服务端，由外部客户端连接，不主动连接远程服务器。

- JSON：字段路径填 `action` 或 `data.action`，接收 `{"data":{"action":"getStatus"}}\n` 时，匹配接口名称 `getStatus`。支持对象层级和数组数字下标，只接受字符串／数字提取值，不运行 JSONPath 表达式或脚本。
- 文本：分隔符填 `|`、序号填 `1`，`device|getStatus|123\n` 匹配 `getStatus`；分隔符留空使用整帧文本。
- 接口名称区分大小写且精确匹配，不可重复；启用后返回配置的 JSON／文本。JSON 回复去除字符串外空白，保留大整数和字符串原文；可选择追加相同结束符。没有 HTTP 方法、路径、状态码或响应头，旧 HTTP 字段保留但不参与 TCP 匹配。
- 未匹配、关闭、字段缺失或消息格式错误时不回复，只记日志。接口开关／保存运行中生效，修改监听和提取规则需先停止。一个客户选择一种协议，同一时间只运行一个 HTTP 或 TCP 客户。
- 每帧及回复最多 1 MiB；每连接独立缓存，最多 64 个连接，空闲 60 秒关闭；待写数据约 2 MiB 上限，停止最多等待 3 秒。日志预览最多 8 KiB、会话最多 1000 条。

`simulator.json` 当前为 schema v3，旧 HTTP／TCP 配置自动迁移。可执行 `pnpm exec node scripts/tcp-smoke.mjs` 验证桌面及真实本机 TCP 流程。不含 TLS、二进制字段解析或脚本。

## TCP 长度头特殊协议（0.6.0）

编辑 TCP 客户，分包协议选择「长度头 + 正文 + 结尾标志」。前 N 位是固定宽度 ASCII 数字文本，可选十进制／十六进制、1–10 位，不足补零；不是二进制整数头。长度单位可选 UTF-8 字节数或 Unicode 码点数，计数对象为线上正文原文（含 JSON 引号、空白、转义），不是解析后的字段值。长度范围可选仅正文或整包（头 + 正文 + 结尾）。

例如 `0016{"action":"get"}#`：4 位十进制、正文 UTF-8 字节数、结束标志 HEX `23`，正文类型 JSON，提取字段 `action`，接口名称 `get`。接口回复 `{"ok":true}` 时，开启自动包装会发送 `0011{"ok":true}#`。选择整包长度时，示例请求应为 `0021{"action":"get"}#`。

结尾按长度定位后校验，正文内可以包含相同标志，也可以发送美化 JSON；头、UTF-8 字符、尾标均可拆包，多包粘连会逐包处理。旧的「按结束符分包」行为不变。JSON／文本解析及字段选择仍独立配置。

开启回复自动包装后，回复总是携带相同规则生成的长度头和尾标；关闭后可沿用原来的原文／仅追加尾标回复。回复长度超过头宽度时不发送并记录错误。非法头、声明长度超过上限、错误尾标会关闭该连接；残缺包等待后续数据或 60 秒空闲超时。正文上限仍为 1 MiB。按整包字符计数时，尾标也必须是有效 UTF-8。不会自动猜测长度含义、搜索花括号或剥离任意未知内容。

配置迁移到 simulator.json schema v3，v1/v2 客户保持旧行为；验证命令 `pnpm exec node scripts/tcp-smoke.mjs --length`。
